Each one is real code in this repo, has a pass/fail test, and can be demoed. The student writes it, runs it, and explains every line. Use AI only to ask "why", never "write it".

Keep a log in `CONTRIBUTIONS.md`: date, who, files, the commit hash, and a sentence on what they learned. Commits by the students' own GitHub accounts are the best evidence.

## Each student should be able to do this live, without help

- Trace one profile through the rules engine: which condition matched, which did not, why.
- Explain what "unknown" does in the three-valued matcher.
- Show where the third-business-day date comes from and why weekends are skipped.
- Change one line, run `npm test`, and watch a test fail, then fix it.

If they cannot do these, they do not yet own the code, and judges (or the exit questionnaire) will notice.
