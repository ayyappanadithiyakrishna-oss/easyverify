Sources: the preserved Claude conversation “Product demo feedback and improvements” (September 24), the supplied Downloads/DESIGN.md Cursor style reference, current official CAC rules/graphics pages, and the local 2026 rulebook. The clearest competition demonstration is a profile change with explainable rule matching: ordinary California employer → FAR contractor, unknown answers → review, changed calendar → changed date. It demonstrates implementation and programming better than a collection of disconnected integrations. No district-specific numerical scoring weights were found; do not invent them.

Implemented visual direction: warm parchment and charcoal themes, sharp 4px controls, system-font substitutes from the supplied reference, restrained orange source/navigation accents, lighter heading weights, real workspace imagery, and consistent dashboard surfaces. A persisted explicit theme preference overrides the operating-system default.

Implemented help: deterministic source-linked answers available to all visitors; optional Llama 3.2:3b answers from the visitor's local Ollama server. No workspace records are sent. Sensitive-number patterns bypass the model. Model output is untrusted and shown as text; official citations and the original source-guide answer remain accessible. Llama can still make mistakes; prompt constraints are not a guarantee of factual grounding.

Implemented biometric experiment: optional browser-only photo comparison using Human 3.3.6. Consent precedes file selection; one face per photo, maximum 10 MB/file and 40 megapixels, no uploads or database writes, no pass/fail threshold, no onboarding mutation. The combined FaceRes model internally computes other predictions; these are neither displayed nor used. This is not identity proof, liveness detection, or work-authorization verification. No accuracy/fairness claims are made from the smoke tests.
